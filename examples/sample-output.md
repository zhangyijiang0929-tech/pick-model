# 三个真实输出示例

这些是 skill 应当输出的样子。格式固定五行，理由必须能指回具体维度。

---

## 例 1：批量抽取（T1，省钱场景）

**输入**

> 从 500 张收据的 OCR 文本里抽出商户名、日期、金额、税号，输出 JSON。

**输出**

```
T1 · 轻任务 → qwen3.7-flash

理由：单步映射 + 每张不到 1k tokens，容错 0（字段错了能一眼看出来，重跑便宜）
粗估：0.8k / 0.2k ≈ $0.0001/次（含 8% 重试风险），500 次约 $0.05
降档代价：已在最低档。若换成 claude-haiku-5.5 ≈ $0.0003/次，贵 3 倍但 schema 遵循更稳
升档门槛：只有当 JSON 直接进数据库且下游没有校验时，才值得升到 T2 求稳
```

这是 skill 最该发挥价值的场景：500 次调用，档位差一级就是 30 倍差价。
注意这里是全表最便宜的模型，仍然建议"先跑 20 张抽样验证 schema 遵循率"。

## 例 2：对外发布的行业分析（T3，一票升档）

**输入**

> 基于这三份研报，写一份 3000 字的行业趋势分析，给投资人看。

**输出**

```
T3 · 重任务 → claude-opus-5.5

理由：总分 5 本应落 T2，但容错维度 = 2（对外发布、判断错了没人能发现）触发一票升档
粗估：40k / 5k ≈ $0.26/次（含 1.5% 重试风险）
降档代价：换 claude-sonnet-5.5 ≈ $0.13/次，省钱一半，但跨文档取舍会更保守、结论更平
升档门槛：已在高档。若要求可验证的定量结论，需要外部数据校验而非更强模型
```

关键在这一档**不该省钱**。判断错一次，代价是投资人的信任，不是 13 美分。

## 例 3：代码库级重构（T3，分数本身够高）

**输入**

> 把这个 2 万行的 Python 模块拆成三个包，保持接口兼容。

**输出**

```
T3 · 重任务 → claude-opus-5.5

理由：总分 8（依赖关系跨文件推 2、代码库级输入 2、架构判断 2、有测试兜底 1、需跑测试 1）
粗估：100k / 10k ≈ $0.60/次（含 1.5% 重试风险）
降档代价：换 deepseek-v4-pro ≈ $0.17/次，但有测试兜底意味着失败可发现，可先试一轮
升档门槛：已在高档
```

这个例子里容错只有 1 分，不是一票升档，而是分数本身够高。两种升档要给用户不同的解释——
前者意味着"错不起"，后者意味着"活儿重"。混为一谈会让用户误判风险。

因为有测试兜底，这里可以建议：先用 T2 跑一轮，测试失败再升档。
这是 skill 该给的可执行建议，不是模棱两可的"看情况"。

## 反例：不要这样输出

```
建议使用综合素质较强的模型，考虑到任务复杂度中等偏上，
Claude Sonnet 系列和 GPT 系列都可以胜任，具体看你的预算和偏好。
如果预算充足建议用更强的模型，效果会更好。
```

问题：没有结论、没有数字、没有降档代价、没有可核对依据。
用户看完还是不知道怎么选，等于白问。
