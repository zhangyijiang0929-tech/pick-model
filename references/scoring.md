# 打分细则

目标是把"这任务有多难"变成可核对、可解释的数字，而不是凭感觉说一句"感觉有点复杂"。
用户会追问"凭什么是 T2"，所以每一分都要能指回具体证据。

## 五个维度，每项 0 / 1 / 2 分

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| **推理步数** | 单步：一次映射或一次判断 | 2–3 步，且中间结果可验证 | 4 步以上，或中间结果无法验证 |
| **输入规模** | < 8k tokens | 8k–60k | > 60k，或需要跨文档比对 |
| **任务类型** | 抽取、改写、分类、翻译、格式化 | 写作、总结、常规编码、数据分析 | 架构设计、复杂调试、数学证明、策略权衡 |
| **容错要求** | 错了能看出来，且重跑成本低 | 错了能看出来，但重跑贵 | 错了看不出来（对外发布的内容、没有测试的代码、给人做决策的依据） |
| **工具与多轮** | 单轮、无工具 | 需要几轮对话或少量工具调用 | 长链条 agent、多工具编排、需要中途决策 |

## 落档

| 总分 | 档位 |
|---|---|
| 0–3 | T1 |
| 4–7 | T2 |
| 8–10 | T3 |

## 边界规则（重要）

1. **落在 3/4 或 7/8 边界时，取高档。** 降档失败的代价是重试 + 返工 + 用户信任，远高于那点 token 差价。
2. **任一维度判断不确定（±1）时，整体取高档。** 不确定本身就是升档信号。
3. **容错要求 = 2 时一票升 T3。** 不管其他维度多低。典型场景：给客户的分析报告、没有测试覆盖的部署脚本、法务或财务口径的判断。
4. **输入规模 > 500k tokens 时直接 T2 起。** 这类任务上小模型的"漏读"问题比答错更难发现。

## 期望成本公式

不要比单价，比**期望总成本**：

```
单次成本   = (输入tokens × price_in + 输出tokens × price_out) / 1_000_000
期望成本   = 单次成本 / (1 - fail_rate) + fail_rate × 返工成本
```

第二项 `fail_rate × 返工成本` 在很多场景里是决定性的：一个 8% 失败率的便宜模型，如果每次失败需要人花 5 分钟收拾，而任务一天跑 2000 次，那返工成本会轻易吃掉全部节省。

`fail_rate` 从 `references/models.yaml` 读，是唯一的主观参数。**必须说明这是估计值**，不要把它包装成精确事实。

## Token 估算

不要假装精确。按这个顺序估：

1. 用户给了具体数字 → 用用户的
2. 用户给了文档 → 粗略按 `字符数 / 2.5`（中英混排）或 `字符数 / 4`（纯英文）估
3. 都没有 → 按任务类型给区间（简单问答 1k/0.5k、单篇文档处理 20k/3k、代码库级任务 100k/10k），并标注"粗估"

输出成本通常远小于输入，但写作类任务输出占比高，不要漏。

## 三个示例

### 例 1：批量抽取小票字段

> "从 500 张收据的 OCR 文本里抽出商户名、日期、金额、税号，输出 JSON。"

推理步数 0（单步映射）、输入规模 0（每张不到 1k）、任务类型 0（抽取）、容错 0（能看出来且重跑便宜）、工具 0（单轮）。

**总分 0 → T1。** 推荐 `qwen3.7-flash`。这是 skill 最该发挥价值的场景：500 次调用，降一档就是省 90%。

### 例 2：给投资人写一份行业分析

> "基于这三份研报，写一份 3000 字的行业趋势分析，给投资人看。"

推理步数 1（需要归纳和取舍）、输入规模 1（三份研报约 40k）、任务类型 1（写作）、容错 2（对外发布，错了看不出来）、工具 0。

**总分 5，但因为容错=2 一票升档 → T3。** 推荐 `claude-opus-5.5`。这里省钱是错的：一篇文章的判断错了，代价是投资人的信任。

### 例 3：重构一个 2 万行的 Python 服务

> "把这个模块拆成三个包，保持接口兼容。"

推理步数 2（依赖关系要跨文件推）、输入规模 2（代码库级）、任务类型 2（复杂调试/架构）、容错 1（有测试能兜住）、工具 1（需要跑测试）。

**总分 8 → T3。** 推荐 `claude-opus-5.5`。注意容错只有 1，说明不是"一票 T3"，而是分数本身够高——这两种情形要给用户不同的解释。

## 反模式

- **不要**因为"用户想省钱"就压档。省钱是约束，不是目标；给出真实档位，再告诉他降档的具体代价。
- **不要**给出没有价格来源的成本数字。价目表读不到就直说读不到。
- **不要**在用户已经在干活的中途插进来评估。那只会打断他。
- **不要**输出超过 5 行的分析。用户要的是一个决定，不是一篇方法论。
